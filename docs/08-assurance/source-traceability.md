# Source authority and contract validation

## Current source obligations

The source/claim/section registers retain stable identities, original source hashes and spans, and their current contract destinations. `source-destinations.csv` maps source obligations to current specification homes. `source-obligations.json` records32 assessed sections and126 scoped obligation groups, including retained, delegated, transformed, owner-qualified, historical-evidence and unresolved components. An inherited accepted obligation does not lose acceptance when an editorial assembly is proposed. Implementation evidence does not create requirements.

Every assessed group retains its source identities, component dispositions, applicable authority and current exact contract references. Public checks validate complete coverage and exact current evidence/authority/registry fingerprints. Original source paths and byte hashes remain identity metadata; routine checks do not open private originals. An unresolved mechanism is not adopted by a routing change.

## Reviewing changed evidence

Read the affected current contract and governing owner decision, inspect every component and preserve original source/claim/mapping identities and acceptance scope. A changed source-to-contract mapping, assessment, authority or target requires explicit re-review. Record the basis and update only affected assessment/evidence fingerprints after that review. Missing anchors, incomplete components, stale fingerprints or unknown identities fail closed. Verification never reseals evidence automatically. Fingerprints identify the evidence reviewed; they prove neither semantic equivalence nor authenticated approval, product conformance or mathematical correctness.

## Routine commands

Use `python3 shared/tooling/verify_documentation.py` for current source/contract/metadata/link checks, `python3 shared/tooling/contract_bindings.py` for section-to-node coverage and `python3 shared/tooling/check_docs_structure.py` for physical documentation policy. Use the shared LikeC4 validation cadence for model changes. Archived project documents are not required inputs; private archival verification is a separately requested operation.
