# Current specification registers

These registers describe current authority, requirements, source identities and exact contract ownership. Accepted obligations retain their scope; proposed editorial assemblies and implementation evidence do not confer acceptance.

- [Document identities](document-inventory.csv), [requirements](requirements.csv) and [traceability](traceability.csv).
- [Source identities](source-manifest.csv), [source sections](source-sections.csv), [claims](claims.csv), [coverage](claim-coverage.csv) and [source-to-contract destinations](source-destinations.csv).
- [Assessed source obligations](source-obligations.json) and the [source authority procedure](../../08-assurance/source-traceability.md).
- [Canonical scope ownership](specification-ownership.csv) and [section contract bindings](contract-bindings.json).
- [Decisions](decisions.csv), [open design/implementation questions](open-questions.csv), [technical debt](technical-debt.csv), [risks](risks.csv), [assumptions](assumptions.csv), [compatibility](compatibility.csv), [contributions](contributions.csv) and [research](research.csv).
- [Actual test evidence](tests.csv). A result has only its recorded source/toolchain/scope; it does not imply product acceptance or a whole-system proof.

Original source paths, hashes and spans identify provenance rather than active reading instructions. Current destinations must resolve to the exact contract or diagram that owns the relevant meaning. Historical document IDs remain reserved without active file paths; they are not missing current specifications. Routine current-documentation checks do not require historical project records or private originals.
