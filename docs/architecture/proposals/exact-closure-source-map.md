## 1. Authoritative bundle and representation types

**Authority:** retain one exact selected-state bundle, including root, ordered contributions/inclusions, exact source states and byte-affecting dependencies. The expanded finite use tree and source map are derived. They cannot replace this bundle or its required sources. A graph with shared/cyclic selected rows is not serialised as an independently authoritative expanded tree.

The following tables specify adapter-owned DTOs/codecs. No Serde, I/O, crypto, clock or authorization is added to pure domain records. Field order below is canonical encoder order; objects reject duplicate/unknown/missing fields, enum tags and variants reject extra fields, arrays preserve order, and null is allowed only where stated. These are persistent adapter layouts, not HTTP/MCP payloads or domain type aliases.

| Type | Exact encoding / validation |
| --- | --- |
| `Id32` / `Workspace16` | Existing exact-width JSON arrays of32/16 integers0..255. Record lookup addresses, logical Node/Revision/Occurrence IDs and context handles remain different typed fields even if all use32 bytes. No public content fingerprint or new global occurrence ID. |
| `L32` | JSON integer0..4294967295, used for composition-local row/source/part/use/fragment indexes. Validate array membership before indexing; counts and `index+1` checked. These are format bounds, not measured safe operating ceilings. |
| `U53` | JSON integer0..9007199254740991, for byte/output offsets and durable counters; disallow fractional/exponent numeric lexemes, negatives, booleans, overflow and rounding. Browser conversion must check exact representability before using a JS Number. |
| `Range` | `{start:U53,end:U53}` half-open, checked `start<=end`; byte cuts must be scalar boundaries of the exact full owned UTF8 source. Empty ranges are explicit, not fake characters. |
| `RecordRef` | `{kind:u32,record_version:u32,id:Id32,generation:U53}`. Immutable object refs require generation0; mutable refs require the exact retained generation. Kind/version must be registered and supported at that position; arbitrary numbers do not grant access or interpretation. |
| `Owner` | Tagged `{kind:"node",node:Id32}` or `{kind:"manifest_local",document:Id32}`. The second denotes that exact composition's owned local prose, not a new logical Node subtype or authorship claim. Actual binding below supplies its immutable/working state. No nearest-owner inference. |
| `ByteSource` | A `SourceRef` plus its validated full `SourceState` material; every range remains relative to this full source, not a selected slice or the output. |

### Strict source-reference variants — choice2A

Each `SourceRef` has exactly `{kind,owner,material,binding}`. `material` is a kind40/version1 immutable record reference. `kind` chooses the complete `binding` layout:

| Tag | Binding fields in order | Required relationships |
| --- | --- | --- |
| `committed_revision` | `{state,record}`; `state` is `{kind:"node_revision",node,revision}` or `{kind:"manifest_revision",document,manifest}` | Node revision requires node owner and that exact revision's actual owner; manifest revision requires manifest-local owner and that document's exact immutable manifest. `record` names the actual authoritative supported state record. No same-node ancestry/derivation conflation or live-head lookup. A record lacking the claimed local source cannot manufacture it. |
| `private_checkpoint` | `{document,node,branch,checkpoint,base_revision,base_snapshot,record}` | Node owner; `record` is the actual immutable checkpoint, currently kind23/version1 where applicable. Retain actual checkpoint/document/branch/base bindings and its private authority. CheckpointId is never RevisionId. A working checkpoint's original full bytes, not a subsequently advanced draft, supply the material. |
| `retained_working` | `{document,branch,draft,generation,sequence,base,acknowledgement}` | Exact acknowledged working evidence. `base` is a tagged node-revision or manifest-revision state as above. `acknowledgement` is an exact supported `RecordRef` to the actual acknowledged-state evidence, not a fabricated receipt. The source state's material record is the retained evidence even after the live draft advances; never reread its current text. |

`SourceState` kind40 payload is `{owner,binding,utf8}`. Here `binding` is exactly `{kind,binding}` using the SourceRef tag and its complete kind-specific binding above, without its material self-reference; `utf8` is a JSON string whose decoded UTF8 bytes are the **full exact owned bytes**. Decode valid Unicode scalars, preserve CR/LF/CRLF and Unicode forms; escaped versus literal JSON spelling is not source normalization. Re-encoding the decoded string as UTF8 must reproduce those bytes. Kind40 is a material record, not a new revision or checkpoint identity. Validate equality with the reference's owner/binding and with item1's actual source/evidence relation. An authenticated copied string labelled with a revision ID is insufficient.

The format does not invent an acknowledgement producer or a missing local-prose format: `RecordRef` is decoded only through supported exact adapters and their evidence relations. Current one-owned-buffer/checkpoint readers cannot supply all variants. If the required original state/acknowledgement/structure cannot be validated, general acquisition is unsupported/incomplete, never successful because kind40 decodes. This is a concrete fail-closed interface dependency on item1/item5, not an unspecified field layout or permission to infer a format.

Retained working material has required recovery lifetime; immutable bytes at a stable material address do not make it a permanent historical version or public checkpoint. Recovery bundles are not automatically exposed in history. No per-autosave permanent capture or new cleanup/release event follows. Existing immutable references/history remain intact; recovery records remain protected while depended on. Until a separately approved release mechanism exists, storage may retain unreferenced recovery material and must refuse on capacity rather than delete required evidence or promise unlimited autosaves.

### Bundle kind39 payload

Fields, in order:

```text
{document:Id32, purpose:"acknowledged_recovery"|"immutable_reference",
 interpretation:RecordRef43, root:L32,
 sources:[SourceRef], structures:[FrozenStructure], rows:[SelectedRow]}

FrozenStructure = {source:L32, origin:RecordRef, contributions:[Contribution]}
Contribution = {kind:"run", range:Range}
             | {kind:"include", occurrence:Id32, role:"include",
                target:Owner, notation:Range|null}
SelectedRow = {source:L32, structure:L32|null, selection:Selection, parts:[Part]}
Selection = {kind:"owned_ranges", ranges:[Range]}
          | {kind:"composition_ranges", ranges:[{start:Position,end:Position}]}
Position  = {kind:"before"|"after", contribution:L32}
          | {kind:"inside_run", contribution:L32, source_byte:U53}
          | {kind:"empty_source", source_byte:0}
Part      = {kind:"copy", contribution:L32, fragment:L32, range:Range}
          | {kind:"include", contribution:L32, fragment:L32,
             occurrence:Id32, role:"include", target:L32,
             notation:Range|null}
```

`FrozenStructure` retains the actual complete contribution order and source/notation relation for its exact source. `origin` pins the actual supported authoritative structure/state record acquired by item1; validate that its decoded structure is exactly this table, not merely that the RecordRef exists. The bundle retains this order as required evidence. Full run/notation ranges cover the full owned source in order without overlaps/gaps; graph-only includes occupy their declared positions between those runs without bytes. Empty source can have graph-only inclusions. Nonselected include targets name logical owners only: they do not acquire selected rows or force unrelated source expansion. Extra metadata is still charged and must be authorised; if full structural evidence cannot be acquired within scope, fail explicitly rather than fabricate ordinals. `composition_ranges` requires a resolving structure index; `owned_ranges` may use null and executes no implicit includes. The selected program must match this table and exact fragment membership; an include target row's source owner must equal its full contribution target. An original structure adapter that lacks this relation is unsupported until actual correspondence exists.

Indices are scoped to this bundle, not identities across bundles. `root` resolves in `rows`; every selected include target resolves; `source` resolves in `sources`; a nonnull `structure` resolves in `structures` and names the same full source. `contribution` is its ordinal in the authoritative **full** structural contribution sequence for that source/state, established by item1, not merely its index in the selected `parts` array. This preserves exact membership when excluded neighbours or several inclusions share a byte cut. `fragment` indexes the selection-range list in exact requested order. The list can express discontiguous fragments without joining their original ranges or inventing a separator. Overlap/repetition is permitted only when explicitly part of the admitted ordered intent; each output contribution is charged again.

A composition range selects contributions by authoritative structural order/context, not coincident parent-source offsets. Before/after B selects B alone at a shared byte cut. `inside_run` refers to a cut inside that contribution's exact owned run; validate the context and scalar cut. Before/after indexes remain distinct at zero-byte stops. Identical structural positions select nothing. `empty_source` is valid only for an actually empty owned source/context. `owned_ranges` copies exactly those ranges and executes no inclusions merely because notation is present. An empty list is an explicitly empty selected result with valid context, not an invalid/missing source bypass.

For each selected range, `parts` is exactly the admitted ordered contribution program. A partial source or partial notation fragment is a `copy` with its full source/contribution/fragment context; it does **not** become an executable include. Whole selected structural includes are `include`, even without authored notation. A nonnull notation range must be nonempty and name only the existing including-source span; no-notation is null, never fabricated zero-length syntax. Source-run copies and actual notation spans must agree with the supported full-source contribution relation. Expanded includes replace their whole notation span, if any, by the target row's source result. Cycle stops copy that original notation from the including source when present; otherwise they emit no authored bytes.

Validate full coverage/ordering against item1's selected contribution relation, not by demanding that parent byte ranges alone partition composite output. No phantom, omitted, duplicate or wrong-role inclusion is allowed. Repeated fragment selection is represented by its distinct fragment context, not accidental duplicate slots. Within one full structure, an occurrence identity identifies one placement; distinct parent use paths can reuse its same occurrence ID. Do not assert one global parent for a logical Node. All source and interpretation dependencies required by the admitted selection, including exact stopped targets, must resolve; unreachable table/source entries reject the canonical complete bundle. Structural inclusion cycles remain legal.

Local row equality is **OWNER045 one-step descriptor equality**: exact source state/binding and pinned structural-state origin, selection, ordered contribution/occurrence/role/target references and byte-affecting interpretation dependencies, scoped to this exact bundle. Exclude path, depth, budget, current head, navigation history and cache state. Compare actual source descriptors, not only the source-array index; two source handles can designate the same validated state. Keep exact target row references in equality; do not recursively quotient or merge different descendant selections. Descriptor indexing may accelerate with exact collision-safe comparison, never public fingerprint equality. Arrays/handles need no canonical graph quotient or cross-bundle row-renumbering scheme; a bundle's frozen bytes and references stay exact.

## 2. Interpretation evidence, not a policy-name promise

Kind43 payload is `{program:"hpx-exact-structural",program_version:1,cycle_rule:"one_step_active_descriptor_v1",boundary_rule:"original_notation_or_no_bytes_v1",scope:"source_text",dependencies:[Dependency]}`. A dependency is `{role:"source_syntax"|"source_emission"|"byte_resource",record:RecordRef,range:Range|null}`. These tags define the supported byte-affecting roles, not a grammar inferred from an example. The dependency list is ordered by role and exact record kind/id/version/generation/range; duplicates reject. Retain exact dependency bytes where they affect source. A source-policy version is not a dependency's actual bytes or a grant to fetch it.

For this initial program, dependency records are kind40/version1/generation0 and the optional range is checked against their exact full UTF8 material. Validate their complete source binding through the same source-state adapter before treating their bytes as interpretation data. No recursive interpreter loading or execution of dependency text is implied. A required dependency outside this supported representation fails explicitly; richer resources require another explicit supported profile.

The required evidence relation `Interprets(bundle,full_sources,dependencies,program)` holds only when:

1. Every source reference binds actual supported authenticated full bytes and structural state under one admitted context, with current authority, as required by item1.
2. The supported interpreter establishes that the stored contribution ordinals, source runs, notation ranges where present, structural membership and selected child states agree with that actual state. Saved structure can be authoritative without textual markers; no marker-only parser is assumed.
3. Each program/rule/dependency is the exact supported one used for both selected-state validation and emission; no hidden mutable preference, provider response or current head affects output.
4. For every admitted `copy`, emission copies the exact declared source slice; for an include it uses the exact row selection and accepted recurrence. Stopped notation belongs to its including source; graph-only stops invent no bytes.

Decoder acceptance, an interpreter name, a stored hash or a caller-provided contribution table alone proves none of these. Missing/unsupported interpretation evidence refuses the complete action; no silent newest-interpreter fallback. New grammar/transform support needs its own versioned exact interpretation and correspondence evidence. Fonts/layout/typesetting and historical visual-rendering environments are outside the first source-only guarantee; generated UI labels/warnings stay out of authored source.

## 3. Derived finite uses — choices1A/3A

Derive iteratively in stored fragment/part order, using a bounded active stack of `{descriptor,row,use}`. Assign use indexes in preorder, starting root0. Each use is:

```text
{state:L32, parent:L32|null, incoming_part:L32|null,
 first_child:L32|null, next_sibling:L32|null,
 kind:"expanded"|"cycle_boundary", ancestor:L32|null}
```

Parent is a local **use**, incoming_part names the include's part index in the parent's selected row; the incoming occurrence is obtained there. The selected target is `state`, not replaced by `ancestor`'s row if distinct handles have equal descriptors. Root has null parent/incoming; expanded uses have null ancestor. Each boundary has no children and one real active ancestor use with equal one-step key. Validate preorder membership, unique parent, exact sibling order and no cyclic parent links; the selected-state graph itself may cycle.

Before descending, charge item2 descriptor/slot/use/depth/path costs. If the target descriptor is absent on the current ancestor stack, allocate an expanded use and visit all selected include parts; if present, allocate exactly one boundary use with its exact target and ancestor witness. Pop at completion before visiting siblings. Exhaustion returns L1A failure, never a boundary. Full root-relative paths reconstruct by following parents and reversing incoming occurrence IDs; retain the exact bundle root and fragment context. Bound chain lengths, copied path components and output metadata. Optional path indexes are derived; sharing a selected row or payload never collapses two uses or changes one use's descendant selection.

Manual navigation starts one bounded exact-target action with fresh active stack and the same frozen interpretation/selection evidence and current permission. The navigation root need not be the bundle's original root: its exact row/context is the selected target retained in the boundary. No rewriting of the bundle, implicit head refresh or automatic background chain.

## 4. One typed ordered map — choice4A

The map is an ordered event sequence over the exact source-only output UTF8 buffer. Entry layouts:

| Tag | Fields after `kind`, in order | Meaning |
| --- | --- | --- |
| `enter` | `at:U53,use:L32` | Open this use's structural interval; source-byte length may be zero. |
| `copy` | `out:Range,owner_use:L32,cause_use:L32,source:L32,full:Range,fragment:L32,contribution:L32` | Nonempty exact copied bytes, preserving full-source and occurrence context. Output and source lengths equal and bytes compare exactly. |
| `site` | `at:U53,use:L32,source:L32,source_byte:U53,fragment:L32|null,position:Position` | Exact insertion/caret/fragment endpoint; no ownership span or source character invented. Validate source/structure association; null fragment is allowed only for an actually empty-source context without selected ranges. |
| `stop` | `at:U53,use:L32,target:L32,ancestor:L32,incoming_part:L32` | Exact cycle stop plus required warning/navigation context. Target and ancestor must match the derived boundary, independently of emitted notation bytes. |
| `exit` | `at:U53,use:L32` | Close the same use; preserve even an empty interval. |

`copy.out` entries, ignoring structural entries, form a gap-free, nonoverlapping ordered partition of output `[0,N)`. Zero-length copies are rejected; empty sources/results use explicit sites and structural events. `enter`/`exit` are properly nested, use indexes are exact, each selected include has one child interval, `stop` occurs exactly once in a boundary interval, and event positions are nondecreasing. Same-offset order is retained, never sorted away: enter, relevant sites/copies/child intervals and stop, exit follow deterministic traversal order. An interval's enter precedes its first event and exit follows its last; empty siblings still occupy distinct ordered intervals at one offset.

Ordinary runs use `owner_use=cause_use=current use`. Boundary notation uses `cause_use=boundary` but **owner_use=its parent**, `source=parent row's source`, `full=the incoming notation range`; it is never labelled target/ancestor source. Graph-only boundaries have enter/site/stop/exit at the same output cut and no copy. Admitted root/fragment endpoints, each selected copy range's start/end, and before/after each selected inclusion get explicit `site` entries; preserve duplicates with distinct structural positions. An empty selection on a nonempty source implies no guessed insertion cut; only explicitly admitted positions receive sites. These sites are navigation/ownership evidence, not an adopted command to edit a composite or a new ACL.

Selection resolution uses the identified buffer, event order, exact use and structural position. A byte offset alone cannot choose between two zero-byte siblings, a partial fragment and a whole include, or the left/right owner at a shared cut. The caller supplies an explicit site/context or receives ambiguity; no nearest-text guessing. Preserve nesting/coverage on partial or discontiguous fragments: copies retain original full-source ranges and each fragment's context; gaps in the original source are not gaps in output and have no fictitious ownership.

Warnings, target navigation labels, conflict indicators and transformed widget labels are separate presentation metadata keyed to exact uses/sites. Required cycle warnings cannot be dropped to fit a budget. Generated UI bytes have no `copy` entry in source. A future generated-source transformation would need a separate explicit profile/design; this source-only layout does not smuggle generated placeholders into copied spans.

### Exact UTF8 / browser UTF16 / display relation

Store only full-source UTF8 offsets above. After complete backend derivation, presentation identifies the exact output buffer and map context. Scan that exact UTF8 buffer into Unicode scalar boundaries; count1 UTF16 code unit for a BMP scalar and2 for a supplementary scalar. A UTF16 endpoint inside a surrogate pair, stale context, out-of-range value or ambiguous structural site rejects. For a copied output cut `o`, resolve full-source cut as `full.start + (o - out.start)` with checked arithmetic and exact scalar validation; ownership at the shared end requires its explicit site/context.

A CodeMirror/LF display, HTML table/math replacement or other transformed view requires its own checked display-to-this-exact-buffer relation, including CRLF/CR and replacement widget boundaries. Browser-local sequence/source context and selection/undo remain separate from immutable state. Never normalise source, count UTF16 against another buffer or apply a whole composite buffer to one owner. Initial composite reconstruction stays read-only; authority is rechecked at an eventual owned-source operation, not granted by map presence.

## 5. Deterministic derivation and caches — choice6A

Given the identical validated frozen bundle, supported interpretation/dependencies and chosen exact action root, traversal and emission are deterministic in array order. Emit into a charged staging builder while deriving use/event tables. Charge copies, concatenation/reallocation, equality comparisons, active-key search, parent/witness storage and full path materialisation before work. No expanded tree is needed to begin bounded iteration; only a complete admitted source/map/use result is exposed. Failure discards the incomplete candidate and preserves the last valid view/request under L1A.

Kind42 optional cache payload is `{bundle:RecordRef39,interpretation:RecordRef43,action_root:L32,working_context:WorkingContext|null,derivation_version:1,uses:[Use],map:[Entry],utf8:string}`. `WorkingContext` is `{user:Id32,document:Id32,branch:Id32,recovery:RecordRef41}`. Immutable-reference reads use null; acknowledged-working reads bind the exact protected context/generation as well. Cipher context confines cache bytes to their workspace/epoch; the private scope and current workspace-user permission are revalidated before lookup/disclosure. No plaintext/public cross-user cache identity. Storage cache address is opaque and is not a logical snapshot ID.

Verify exact bundle/interpretation/root/context identity, decode bounds and all tree/map invariants; independently rederive and compare exact uses, ordered map and UTF8 bytes before first use of a persisted cache. A checksum/AEAD/`validated` flag alone cannot establish this relation. A process-local validated entry can be reused only while those immutable bindings remain exact and current authority is rechecked; changing recovery generation or interpretation invalidates it. Validation work counts against the same operation allowance. Skip an oversized cache write without discarding an otherwise valid admitted result; no mandatory cache for success. Do not truncate it and later call it complete.

Only kind42 and optional path/display indexes are discardable derived caches. Kinds38–41/43/44, exact source material, selected dependencies and immutable history are **required evidence**, not evictable because a cache quota is full. Absence of a cache causes bounded rederivation, not selection changes. A warm cache never refunds logical output/use/metadata costs or resets the allowance.

## 7. Effective incompatible-workspace gate — choice8A

### Inspected current boundaries

This is **static source inspection, not a new executed older-reader test**. [Bootstrap](../../../backend/crates/storage/src/keychain.rs) accepts application_id HPX1 with schema1/2, and passphrase/keychain opening both call it before decrypting the catalog. [Command execution](../../../backend/crates/storage/src/lib.rs) rechecks schema1/2 inside its IMMEDIATE transaction before receipt replay. Experimental [temporal guard](../../../backend/crates/storage/src/temporal_save.rs) instead requires marker3 and authenticated feature32. [Record decoding](../../../backend/crates/storage/src/encoding.rs) accepts wrapper1 only and rejects unknown fields/versions. [Authority reads](../../../backend/crates/storage/src/authority.rs) reload catalog kind1; some already-open reads do not independently inspect user_version. The existing connection opens read/write before bootstrap; a schema rejection is not proof that no SQLite handle or sidecar was touched.

Therefore **new optional kinds alone, a capability flag or unknown-field preservation is not sufficient**. Schema3 is already an incompatible experimental reservation and is not repurposed for closures. Candidate schema4 is a new explicit incompatible boundary, not a silent normal-format update or permission to import temporal3 fixtures.

### Selected schema4 design

Keep application_id HPX1 and envelope1. A schema4 opener supports **exactly schema4 for this feature**, validates the expected SQL table set, feature38 at ROOT and its workspace/versions, and an incompatible root **Catalog kind1 wrapper2**. Catalog2 payload order is `{owner,device,owner_label,documents,closure_feature:RecordRef38}`; retained owner/device/documents have their existing meanings, not a substitute for the still-required general workspace-user permission design. The schema4 catalog decoder is explicit and separate; all unaffected old records remain wrapper1 and are never relabelled version2. Require feature generation0 and the exact matching catalog feature ref; wrong/missing/mismatched feature, wrapper or supported interpretation rejects before protected reads/commands. Schema4 requires the existing ADR014 keychain table shape with zero or one wrapper row; feature38 declares its presence. An empty table is unenrolled, not a provider connection or trust installation. Existing enrolled rows and passphrase recovery are retained. New readers retain normal schema1/2 paths unchanged until an explicit upgrade.

The physical schema uses the current exact bootstrap/objects/slots definitions in [storage creation](../../../backend/crates/storage/src/lib.rs), including32-byte IDs, nonnegative slot generation, compound `(kind,id)` keys, strict objects/slots tables and bootstrap workspace16/epoch1/wrapper106 constraints. Add no new SQL table for closures; `keychain_unlock` always retains the existing ADR014 definition in schema4; a schema1 upgrade creates it empty without enrolling. Reject unknown tables, malformed definitions or unexpected bootstrap/keychain rows. Replacing catalog1 during upgrade increments its actual slot generation with checked arithmetic and seals wrapper2 under that new generation; never reuse ciphertext with a changed AAD generation.

Unsupported current cold readers reject marker4 at bootstrap before normal catalog/feature use, including passphrase and keychain paths. If a live old handle later enters normal command execution, marker4 rejects before replay/writes; temporal3 guard also rejects4. Catalog wrapper2 additionally causes old generic wrapper1 authority/catalog decoders to fail even if the caller omitted a schema check. Existing old plaintext already in a process cannot be revoked by a format marker; quiescence, not an invented confidentiality proof, is required. No claim is made that arbitrary unknown binaries or hostile SQL tools obey the gate.

### Required future upgrade procedure and acceptance

No upgrade implementation is performed or authorised by this design. An actual migration needs separate owner authorisation and a verified supported source-version route:

1. Quiesce all HPX writers/readers and keychain/backup operations, close owned handles and hold an exclusive maintenance boundary over the actual workspace. If absence of stale handles/other writers cannot be established, refuse. Existing WAL single-writer locking alone does not establish application quiescence or prevent old cached transactions.
2. Create, finish and durably sync an exact restorable SQLite backup including committed WAL state; verify workspace, schema, key wrappers, all object/slot identifiers/generations/ciphertext and keychain state through the actual backup API. No raw main-file-only copy or private test mutation. The backup remains the rollback route until new-reader acceptance.
3. Under exclusive upgrade control and one atomic database transaction, validate source schema1/2 and actual catalog/wrappers, preserve immutable object/history bytes, add feature38, replace only root catalog with explicit wrapper2 and matching feature ref, and set user_version4. Preserve an existing keychain wrapper/table and passphrase key; a schema1 route creates only the empty ADR014 table and carries no enrollment. Add no fabricated general closures for legacy one-occurrence snapshots: legacy records remain exact, with their existing reader dispatch; new bundles are created only from actual validated input through separately authorised operations.
4. Commit only after the feature/catalog/schema agree and exact before/after preservation checks succeed, durably sync, then reopen with the supported schema4 reader and verify exact legacy reads/history/recovery and unsupported-reader refusal. Interrupted/inconsistent staging fails closed. Never lower user_version to make an old binary open the new file. Restore the exact verified pre-upgrade backup only under exclusive explicit recovery, without merging later schema4 writes into it.

The future schema4 guard must run within **every** protected read/write/replay/backup/enrollment transaction, before disclosure or mutation, not just initial opening. No old mutable schema1/2 write path is valid against4; old immutable records can be read only through the supported schema4 compatibility dispatcher with current authority. Feature/catalog guards are integrity/compatibility checks, not per-user authorization. No concurrent migration/new writes, in-place silent repair, partial feature enablement or fallback interpretation.

Actual supported older binaries must be inventoried and tested cold and with pre-opened handles, including every direct write/replay/keychain entry point. If any can damage affected state, the upgrade remains unavailable until the concrete gate is corrected and reverified. Source inspection here justifies this design boundary; it is not evidence that the future upgrader or every older reader already enforces it. Physical table/backup/exclusive-control and multi-user enforcement implementations remain item5 acceptance work; the selected field layouts and refusal requirements above are complete.

## 9. Cost obligations and future conformance — unexecuted

Storage is proportional to retained full source material plus selected rows/parts/dependencies and required recovery/reference bindings, not to infinitely expanded paths. Actual indexes and buffers can still dominate. Derivation costs include expanded uses/slots, active descriptor comparisons over their full field/byte/target lengths, source copying and map/site/warning entry counts; paths reconstructed on demand cost the full traversed/copied components. Branch-local detection may be quadratic in depth without an exact index; no unconditional linear-runtime claim. Derived caches may exceed bundle size dramatically; their storage cap is separate. The existing16MiB envelope/JSON escaping limits can refuse a large record before any wider logical budget, and are no measured latency/memory promise.

Item2 must meter real decoding/source verification, index building/collisions, comparison prefixes, active frames, repeated uses, parent/path copies, emission builder flattening, map metadata, browser UTF16/display/render work and peak old-view-plus-candidate/concurrent resources. Measure these against the concrete chosen implementation before safe numeric defaults. This document chooses local32-bit representation and U53 offsets, not safe operational capacity.
