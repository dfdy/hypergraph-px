## Result, authority and completion boundary

L1A initially provides either the requested **complete** exact reconstruction or an explicit failed request. A limit failure preserves the last valid view, selection, editable state and exact frozen request context. It never exposes a shortened reconstruction as successful. The user may explicitly choose a smaller scope or deliberately retry within supported limits. Incomplete previews and incremental/streamed completion are deferred capabilities, not permanently excluded; transport chunking alone does not enable them.

L2A selects engineering-chosen initial budgets with clear failure/recovery, no user-facing tuning controls, privileged override, new administrator or unbounded bypass. Safe numbers require measurement against a concrete implementation and supported platforms. Read authority and admission remain distinct: available capacity grants no access; permission grants no unlimited resources. Browser and MCP use the same backend policy, with adapter-specific presentation admission added where applicable.

This contract completes the accounting, failure, bounded-navigation and future-conformance **definition**. Numeric defaults, executable suppliers, item3 representations and item5 implementation/proof correspondence remain dependencies. They do not keep item2's specification checklist open or establish measured/end-to-end protection. No persistent reconstruction-profile change is required: operational allowances are execution conditions, outside the frozen source-emission/cycle interpretation. A genuinely required later format/API change needs its own concrete proposal and approval.

## One intent, one accounting lifetime

The proposed execution contract binds a ledger to one authorised intent: acting workspace user/context, exact root and selection, historical or acknowledged-working candidate, frozen interpretation and exact target for navigation. This is a logical binding, not a selected ID, wire field, cursor or persistent journal.

Use componentwise nonnegative counters with declared finite limits. For every charge/reservation `d`, test `d <= limit - used - reserved` with checked arithmetic **before** beginning the bounded unit of work. Underflow/overflow or unrepresentable lengths cannot wrap, saturate into acceptance or trigger a huge allocation; classify as unsupported size/resource refusal without alleging corrupt content unless independently established. Products, encoded-length expansion, UTF16 capacity, array capacities and index/path arithmetic require the same checks.

Reserve a conservative enforceable upper bound before an indivisible step; for variable-size input use bounded reads/decodes and charge each bounded unit before consumption. An untrusted length is no permission to allocate it. If no trustworthy bound or interruptible bounded primitive exists, refuse admission before invoking it. Establish authentication according to the existing envelope boundary; do not claim partially authenticated plaintext is valid. If the current crypto/decoder needs a full buffer, reserve all simultaneously live buffers and workspace before starting it. No compression/codec is introduced here; any future expansion decoder must bound decoded size/work independently.

Completed logical work charges are monotone until that intent terminates. Release unused reservations and physically freed live memory; never refund work already performed. Cancelled/failed work still counts toward aggregate safeguards. Logical output includes required complete source and metadata even if a cache avoided recomputation. Cached physical work may be charged at actual bounded cost only after exact identity/interpretation/authority validation; its output/use/metadata obligations remain. Eviction or a cold retry cannot silently create a new allowance.

Internal preparation gates, phase transitions, supplier retries, transport chunks, cache misses/hits, process adapters and browser conversion all belong to this lifetime. A supplier returning its local result cannot reset the enclosing ledger. Bounded recovery/reconciliation overhead is reserved within that operation or explicitly refused. A deliberately repeated user request is a new intent with fresh finite limits and aggregate admission; an automatic retry remains the old operation. Do not reinterpret uncertain writes or invent new operation IDs to settle them. No new write is part of this read-only design.

## Phase and resource accounting

The dimensions below are independently bounded; passing one cannot compensate for exceeding another. Count empty records, zero-byte contributions and metadata-only stops. Distinguish unique admitted records from expanded **uses**. With two uses of each child, an acyclic chain of distinct selected rows can have exponentially many uses despite a small table and no cycle.

| Phase / supplier | Charge or reserve before work | Required accounting and refusal boundary |
| --- | --- | --- |
| Intent and authorised acquisition | Context validation, request parsing, lookup/permission attempts and dependency-discovery steps; pending/read concurrency slots and read workspace | Limit input/context lengths and each acquisition attempt, including missing/denied results; bound actual index/search/scan effort, not just returned records. Establish only authorised diagnostic detail. Avoid enumeration through errors. Reserve before reading; if size unknown use bounded reads or refuse an indivisible fetch. |
| Encrypted/decrypted acquisition | Physical I/O bytes/attempts plus ciphertext bytes, plaintext bytes, authentication work and live crypto buffers | Independently bound on-disk/envelope sizes and authenticated decoded payload sizes; include nonce/tag/wrappers, simultaneous ciphertext/plaintext and transient copies. Cache reuse still validates frozen bindings/current authority. Repeated read/retry costs count even for one logical record. |
| Decode and input validation | Encoded units scanned, decoded nodes/fields/strings/arrays, source bytes/scalars validated, structural entries and validation comparisons | Reserve collection sizes before allocation; reject over-limit declared lengths early. Bound invalid-input scanning, UTF8/range checks, ordering/duplicate/completeness checks and error construction. Full-source verification may exceed selected output size: a tiny range cannot excuse unbounded full-source loading. Zero-byte structure has positive entry/work cost. |
| Frozen selected table and descriptors | Unique rows, total ordered slots, descriptor fields/bytes, table lookups, comparisons and index-build/collision effort | One-step structural equality is semantic equality, not constant-time computation. Charge actual fields/bytes/slot references compared, including long equal prefixes and failed matches. Bound sorting, scans, collision resolution and any canonicalisation. Hashes/indexes may accelerate lookup only with exact collision-safe equality and measured costs; no identity/hash mechanism is selected. |
| Expansion / cycle decisions | Each visited expanded or stopped use, each inspected child slot, active ancestor candidate comparison, selection transition and traversal step | Repeated siblings are charged separately even with shared payloads; empty children/stops still consume work/use limits. Branch-local structural recurrence decides cycles. A global visited cache or a depleted budget cannot produce a cycle witness. Reserve output-use records before constructing them. |
| Paths, depth and witnesses | Peak active depth, stack frames, path components/bytes retained or copied, ancestor/target witness size and lookup/comparison work | Bound both depth and aggregate path storage/copy effort: copying every length-d path can cost the sum of path lengths, not merely use count. Persistent/shared path structures remain item3 choices and still incur reference/index/lifetime costs. No unchecked recursive call stack. Reserve a frame/path/witness before descent or recording. |
| Source emission | Total exact emitted UTF8 bytes and copy/scan/concatenation work; builder capacities, transient and final buffers | Repeated sources count once per output use. Include retained original notation at cycle stops; graph-only stops emit no invented source but retain positive metadata charges. Reserve bytes before each append/copy; include repeated reallocation/copy and flattening. Staged bytes stay private/incomplete until full result admission. |
| Source map / warning/navigation metadata | Entries, encoded and resident bytes, full occurrence/owner/range context, stop targets/ancestors, warnings and associated construction work | Bound source-map segmentation, zero-byte structural selections, boundary metadata, diagnostic text and all copies independently of source length. No silent coalescing that loses occurrence/context or warning suppression to fit. If required metadata cannot fit, the complete request fails. Error reporting itself needs a small bounded reserve. |
| Delivery / browser conversion and render admission | Encoded transfer bytes/chunks, decode buffers, exact UTF8-to-UTF16 scan/output units, mapping indices, render nodes/widgets and render preparation work | Bound escaping/serialization expansion and simultaneous backend/transport/browser buffers. Before installing a candidate view, admit its source, map, warnings and presentation costs coherently. Bound expensive table/math replacement/render operations by input/structure limits or isolated cancellable bounded work; a source byte ceiling alone is insufficient. Preserve exact buffer-bound coordinates and reject split/stale mapping. No normalisation. MCP presentation has its own bounded materialisation while backend rules remain common. |

Logical meters express semantics and algorithm work/output. Physical safeguards independently bound live and peak resident memory (including allocator overhead, shared ownership, old view plus candidate and concurrent copies), CPU, I/O, elapsed/deadline time, pending queues and active requests. Timeouts do not prove a logical budget was exceeded, nor does a logical step counter prove a memory/CPU bound. Bound maximum time between cancellation/deadline checks and the cost of an indivisible primitive; an uninterruptible decoder/renderer cannot acquire a deadline guarantee by checking only afterwards. Platform primitives and enforcement strategy require later evidence.

Aggregate admission must reserve finite memory/work/concurrency headroom across active intents and queued work per workspace/user and process/service. Include transport/browser work and cancellation cleanup until resources actually release; do not count a cancelled task as freed while it still computes. Avoid starvation and restart/retry storms; exact scheduling/fairness mechanism and quotas are unselected. A request within local limits may still be refused as temporarily busy. A process watchdog or OOM is evidence of inadequate safeguards, never successful completion or proof that the underlying content is invalid. After a crash, restore/revalidate exact retained state through ordinary recovery; do not promote incomplete buffers.

## Conditional supplier interfaces

Use item1's completed supplier result relation and gates without pretending its suppliers exist. Each responsible application/storage/interpretation/domain/presentation boundary must accept the enclosing allowance/cancellation context (or enforce an equivalent non-bypassable bounded delegation), return bounded results and trustworthy accounting for actual work, and identify whether a complete result was established. A supplied boolean or post-hoc total cannot justify already unbounded work. These are obligations on future interfaces, not signatures or wire contracts.

- Application coordination admits the intent/current user, obtains coherent exact evidence and controls aggregate reservations. Authentication, unlock and permission remain separate; no pure-domain permission/loader callback is introduced.
- Storage/crypto adapters enforce read/size/authentication/codec bounds before supplying item1's full-source bindings. If exact consistency cannot be established within allowance, return non-completeness while retaining the frozen request and required recovery evidence. No fallback to current heads or last Commit.
- Structural interpretation supplies ordered structural contributions and exact endpoint/fragment relations with its discovery/validation costs accounted. Absence of textual notation does not remove structural work. Inaccessible dependencies fail under item1 without leaking their existence.
- Pure planning consumes supplied finite inputs with explicit bounded traversal/comparison/path/output obligations; no serialization, I/O, clock or permission authority enters domain records. An application supervisor may enforce physical deadlines while deterministic planning accounts logical work.
- Emission/map and presentation suppliers stage one coherent candidate and expose completion only after source, selections, cycle witnesses, warnings and coordinate/render admission all succeed. Transport can be chunked internally; the current valid view remains authoritative until complete candidate installation. A late, cancelled or superseded response cannot replace newer typing or selection.

If a supplier cannot expose or conservatively bound required costs, that implementation is not conformant; it is not a new owner-policy decision or permission to omit the phase. Client disconnection/cancellation must propagate through pending work. Disclosure-time authority remains required under the eventual permission/revocation design. The resource ledger is neither an authority token nor proof of item1 admission.

## Failure and explicit recovery

These are semantic classifications for future behaviour, **not** an adopted error enum/API. Every failure ends the current complete-result attempt, with bounded authorised diagnostic detail and the last valid view/context retained. If no valid view exists, show an explicit failed/empty state without inventing a successful result.

| Classification | Meaning and user-visible recovery |
| --- | --- |
| Logical work/output/depth/metadata or representable-size limit | Say the requested reconstruction could not complete within supported limits. Offer deliberate retry or a separately explicit smaller scope. Do not offer a tuning slider, privileged bypass or silently auto-shrink/retry. Preserve the original frozen request for the same-target retry. |
| Physical capacity / busy / deadline | Explain temporary capacity or time refusal without claiming a cycle, corruption or a changed historical result. Permit deliberate retry subject to aggregate admission. A larger logical limit alone cannot cure physical capacity or guarantee success. |
| Cancellation / superseded request / disconnected client | Stop bounded work, discard incomplete candidate, release actual resources and retain last valid state. No automatic navigation continuation or late view replacement; distinguish a user cancellation from timeout. |
| Missing / denied / corrupt / unsupported required input or interpretation; inconsistent/stale candidate | Apply item1's truthful, disclosure-safe failure distinctions. Do not call all failures resource exhaustion, fabricate empty bytes or repair by following heads. Preserve exact intent/evidence; if it can no longer be reacquired, say so. A refreshed/new candidate requires explicit distinct intent. |
| Internal accounting / supplier violation | Stop exposure and report bounded failure; retain recoverable state and engineering diagnostics within confidentiality limits. Never declare complete because output was already emitted internally. |

Failure never prunes immutable history, mutates saved relationships, changes a successful historical result, rolls back a valid acknowledged composition or releases required recovery material as an evictable cache. Smaller-scope selection can change the result only as a **new explicit intent**, identified distinctly from the failed complete request; it cannot retroactively shorten that request.

## Bounded cycle navigation and budget independence

Every deliberate click-through names one exact stopped target/context under the frozen cycle interpretation and starts **one** bounded action with current authority and aggregate admission. It may itself stop at valid warned cycle boundaries or fail explicitly. Never automatically follow its new boundaries, prefetch an unbounded chain, accumulate background recursion or turn retry into hidden click-through. Ordinary reference cycles and revision ancestry retain their separate meanings.

For the same valid frozen inputs, selections and source/cycle policy, any two successful executions with adequate allowances must preserve identical selected versions/occurrences, emitted source bytes and semantic cycle decisions. A higher adequate budget can turn refusal into the same complete exact result; it cannot move a cycle boundary or select newer content. Operational allowances may change success/refusal and diagnostics/timing, not successful historical meaning. Physical refusal or authority changes may still prevent success. This is a conformance obligation, not a theorem proved by the existing finite-state model, whose output-use check occurs after conceptual construction.

## Representation and measurement dependencies

Item3 must supply bounded actual costs for selected-row/equality representation, table indexes/collision handling, path sharing/copying and witness construction, source builder/flattening, source-map segmentation, structural zero-byte entries and UTF8/UTF16/render mappings. It must document worst cases or enforceable conservative upper bounds before numeric admission can be implemented. Do not infer linear runtime from finite conceptual termination or `O(uses + bytes)` while ignoring descriptor comparisons and path copies.

Before selecting initial finite engineering constants, measure disposable synthetic fixtures on the declared minimum supported platforms/toolchain: cold/warm acquisition and cache misses, high equal-prefix comparisons, wide/deep/repeated-use inputs, maximum source and metadata ratios, peak live memory including old view plus failed/new candidates, encryption/decode/serialization copies, CPU/I/O/deadline/cancel latency, browser table/math/render amplification, and mixed concurrent users/adapters. Record exact binary/source, platform, input shapes, instrumentation, peak/variance and failure points; choose conservative headroom for runtime/allocator/UI responsiveness and aggregate use. Verify boundaries and fault paths, not just averages. No numbers are asserted or measured in this document; absent a supported measured envelope, real-data operational acceptance remains closed. Benchmarks need no owner guess or new tuning policy.
