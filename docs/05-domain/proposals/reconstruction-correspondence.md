## Subject and exact inputs

For an operation intent `q`, authenticated application evidence `E`, selected-state bundle `B`, and byte-affecting interpretation inputs `I`, the item1 relation `Admits(E,B,I)` must be discharged by actual suppliers rather than assumed from a caller-created table. The names are mathematical contract variables, not serialization DTOs. `E` includes authenticated exact owned source and structural-position evidence, acknowledged-working or immutable-reference purpose, exact selections/fragment context, current access and the original operation/read view. `B` and `I` use the OWNER055 contract rather than an independently invented closure representation.

Exact means logical identity, immutable source or retained working generation/sequence, composition-local parent/occurrence choices, full-source UTF8 coordinates and exact original bytes/line endings. Equal labels/text, current heads, filesystem times, hashes supplied without independent context, cached use indexes and newest observed replies cannot stand in for this evidence. Structural membership includes coincident and zero-byte boundaries; partial source fragments retain context without silently selecting an entire inclusion.

2. Check each adapter-to-model conversion and its negative cases before using the existing Lean theorems as evidence for an integrated result. Differential/property tests compare exact ordered uses, bytes, maps and failures, not just counts or equal rendered text.
