## One application command/query boundary

Every protected browser/MCP/chat operation enters application admission with `{workspace,authenticated_actor,operation_id,operation_kind,target_context,expected_state,payload}`. The authenticated actor is derived by the adapter/session, never trusted from a submitted user label. Commands use exact source/branch/draft/selection state and original operation identity; queries use a frozen bounded read view. Application policy supplies current capabilities and permitted exact input evidence to pure-domain planning; storage publishes below that boundary. No internal HTTP hop, new process/service/crate, public external API product or direct MCP SQL writer is required.

Mutations return attributed exact original results/receipts or explicit denial/conflict/failure/uncertainty. Identical operation reuse reconciles the original frozen request/result before mutable preconditions are reapplied; changed reuse conflicts. Current authority still guards protected receipt payload release. A denied reconciliation discloses neither result existence nor private outcome metadata; the UI retains uncertainty rather than issue a new mutation. Cross-adapter operation identities/digests mean the same logical intent, not independent browser/MCP operations.

## Chat interaction lifecycle

`PrepareInteraction` freezes ordered authorised exact prompt/context node revisions, original operation identity and the acting workspace user. All application-supplied instructions/retrieval/tool context actually sent are included; credentials/keys/private unrelated drafts/provider-internal thoughts are excluded. Record recoverable pending interaction65 before disclosure. Ordinary graph creation always has known origin and explicit parent/position or equivalent machine context; structural placement is not invented from missing notation.

State transitions are `prepared → disclosing → observing → closing`, with `uncertain` on unknown external completion. Cancellation stops further authorised work where possible but cannot recall delivered context. Each observed partial message becomes an exact recoverable ordinary node/source reference before it is reported durable; accumulating UI text that is not acknowledged remains visibly pending. Normal Save/Commit semantics apply to those nodes. This does not make each streamed token an immutable historical event.

`CloseInteraction` atomically freezes manifest64 and terminal status `complete`, `failed` or `cancelled` with exact actually observed parts, source bindings, participants and original receipt. Failure/cancellation retains all acknowledged observations and actual disclosure evidence without fabricating a response. A later continuation creates a new manifest revision linked to the prior one and a new explicit operation, not a silent rewrite of old context. Reopening reconstructs retained supplied/observed content; no provider re-query or latest-head substitution. Inference runs on the machine user's side; HPX supplies chat/MCP graph access, not a model-call orchestrator or inference-provider account.

Protected pending interaction, private drafts and terminal private context are not automatically shared by committing another document. Publishing shared context is an explicit normal graph publication with exact disclosure scope and current permissions. Attribution distinguishes observation, declaration, inference, adoption and actual resolver from original authorship/truth. Historical interaction links are immutable; private lineage is not leaked through a public manifest.

## MCP binding and tools

Design profile **MCP2026-07-28 / stdio** carries UTF8 JSON-RPC messages over the standard newline-delimited subprocess binding. The same distributed HPX executable may run a thin stdio adapter role that forwards to the existing authenticated encrypted runtime; it holds no workspace writer or separate policy engine. It is not a Node runtime requirement. Machine credentials arrive through a protected local enrolment/credential channel, never transcript arguments, source or logs. The adapter validates the configured exact runtime TLS identity/origin; failure does not downgrade to HTTP. Direct network MCP/legacy profiles are unsupported in this initial profile rather than silently negotiated. The normative transport is the [official stdio specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio); a standards pin is a design choice, not an interoperability test.

The logical tools are `select_target`, `read`, `graph`, `save`, `commit`, `history` and `operation_status`. `graph` accepts an explicitly tagged query or authorised graph command (including relation/create/Fork/Link/Embed/Merge/Copy where supported) with the same target/state/operation envelope;it is not read-only graph permission or a raw graph writer. These adapt existing logical application operations; `select_target` changes only the MCP context locator. There is no privileged generic SQL/raw-record tool, actor override or provider call endpoint. Tool JSON schemas are generated from future adapter DTOs; persistent schema5 records are not reused as transport DTOs. Exact current HTTP acceptance remains frozen until reviewed implementation adds this separately versioned MCP profile.

`select_target` validates `{workspace,node,document,branch,view_context,owned_source_refs,expected_state,creation_position}` under the actor's current rights and returns a random32-byte opaque in-memory handle. It binds workspace/user/session, exact target/source/selection/interpretation and expected state. The handle is never an authorisation grant. Every subsequent tool call supplies handle plus original operation ID/expected state, revalidates actor/permissions and rejects an expired/invalid/context-mismatched handle before protected data loading. Mutation success consumes its captured state; obtaining fresh context for a new intent requires explicit selection/read, not ambient retargeting. Lock, session termination, process restart, relevant source change or policy generation change invalidates handles; original-operation reconciliation remains possible through the authorised status path without replaying a fresh edit.

Machine ranges are exact owned UTF8 ranges; browser UTF16 conversion is explicitly against the same owned source. Save/Commit preserve identity unless an explicit Fork/derivation operation is requested. MCP cannot edit another user's pending draft merely because it can read the published node. It cannot self-grant, bypass human-equivalent review policy, or treat provider/model/session/chat as another workspace user.

## Unexecuted acceptance

Run each supported read/graph/Save/Commit/history/reconciliation intent through browser and MCP with two humans and two providers. Compare exact bytes, source bindings, attribution, receipt identity and denied/revoked/stale results. Test tampered/cross-workspace/restarted handles, permission changes, lost replies, duplicate operations, partial/cancelled disclosure, exact context reconstruction and source/selection/Undo preservation. Pin actual MCP client/adapter version and transport traces with secrets excluded. These are requirements; no MCP provider is connected and no product adapter is implemented here.
