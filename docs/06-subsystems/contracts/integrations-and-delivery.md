## Rights evidence and scope

RightsEvidence66 is attributed evidence about an exact subject, not a permission grant or inference of authorship from edit/adoption. Keep original licence/source text and evidence references; disputes/reviews append revisions. Unresolved rights conflicts do not block otherwise authorised export: append a readable report of permitted subject identifiers, claimant/licence statements, dispute status and evidence scope. Omit undisclosable private evidence and label the report's scope without revealing hidden identities/counts. User labels, provider credentials and observation of text do not prove ownership. Confidentiality and current custody/egress policy remain mandatory even when a rights report is requested.

## Exact export plan and conversion boundary

`PrepareExport` freezes exact designated branch or explicit selected branch/bundle39, byte-affecting interpretation43, captured citations/style/templates/assets, chosen writer profile, selected supplements and policy generation into immutable private ExportPlan70. Supplements are explicitly selected from alternative branches, provenance, annotations and graph relationships; they are not added from newest heads. Check every required source/dependency/history grant. Preview is source-neutral and uncommitted; execution revalidates current permissions and the exact reviewed plan without refreshing mutable provider data.

Selected converter baseline is **Pandoc3.14**, bundled as a platform resource in the distributed Rust executable, extracted only after content-hash verification to a new private controlled directory and invoked by absolute path without a shell. The release manifest pins executable bytes/architecture, exact licence/notices/source obligations and all dependency/resource hashes. Each release performs a licence/provenance review before compilation/distribution; no binary has been downloaded, reviewed for redistribution or installed by this design. Current [official release history](https://pandoc.org/releases.html) identifies3.14; the pin is independent of HPX application/API/schema versions. Missing/wrong-hash/unsupported resources return unavailable; no system Pandoc fallback, network installer, PATH search, user filter or external template lookup.

Clear inherited converter data/plugin/search environment; provide only frozen private input/resources and an explicit private working directory. Disable raw executable filters and remote resource fetching; hostile input cannot select subprocesses, arbitrary local paths or network dependencies. Process-level sandbox/no-network enforcement and bounded CPU/memory/temp/output admission are release acceptance gates, not guarantees provided merely by passing a flag. Output uses an exclusive new destination and is released only after plan/current-policy revalidation; cancellation/failure cleans private temporary artifacts under the original job, never arbitrary user paths. The original sources, selections and history are not modified.

Unsupported PDF structures retain readable fallback/loss reports. Actual native renderer/resource tests are required before enablement; no PDF binary output is produced by this specification.

Bibliography/citation resources are frozen CSL/locale/bibliographic records with full style identity/version, not ambiguous names such as “Harvard” or a live default. Source-byte reconstruction is independent of layout/fonts; export rendering need not be byte-identical across unpinned platforms.

## Zotero capture

The user explicitly selects Desktop-local API or cloud Web API, library/collection/items and disclosure scope; no fallback between them. Both pin Zotero API3 and require matching response version. The [official API3 contract](https://www.zotero.org/support/dev/web_api/v3/basics) specifies cloud HTTPS at `https://api.zotero.org`; the separately selected [local API](https://www.zotero.org/support/dev/web_api/v3/local_api) is `http://localhost:23119/api/`. The native integration limits this local profile to explicit bibliographic metadata/selection with no HPX credentials or protected manuscript query; it never makes a browser/runtime HTTP path or disables runtime TLS. Reject redirects/non-loopback resolution and prohibited disclosures; a policy requiring authenticated encrypted connector delivery reports local-profile unsupported, never silently falls back to cloud or plaintext. The user enables any Zotero preference separately; this specification connects nothing. Desktop loopback origin and cloud authenticated origin are separately configured and validated. Credentials remain in the protected integration boundary, not nodes/context/logs. Operations are read-only; use captured exact metadata/version, response evidence and style/resource refs in CitationCapture69. Historical export uses those bytes and never refreshes a citation or queries a library automatically. Lookup text derived from protected content requires current authorisation/egress even when the returned record is public. Import malformed/unsupported metadata fails without guessed fields. Actual endpoint/client profiles are recorded in release capability manifests and must pass provider-specific acceptance before connection.

## Local spelling and inert Word review

Select bundled **nspell2.1.5** as the local browser spelling baseline; its upstream [package metadata](https://github.com/wooorm/nspell/blob/main/package.json) identifies the version and MIT licence. The release dependency review pins its exact package/transitive bytes, bundle and separate dictionary licences/notices. Initial bundled English variants are explicit en-GB/en-US dictionary resources; language choice is visible, unsupported languages report unavailable, and user dictionaries remain workspace-user private data. No external spelling service or dictionary network fetch is selected. Browser bundling does not create a Node release-runtime requirement.

Spelling suggestions bind exact owned source/version and scalar-safe range; applying a chosen correction is an ordinary undoable draft edit with current expected state. Stale suggestions disappear or require explicit regeneration; dictionary entries and suggestions never grant source authority or create a Commit. Preserve original text/line endings and source beneath rendered widgets.

Word review import accepts only explicitly selected `.docx` source and target branch/snapshot/context. Parse the ZIP/XML inertly under entry/count/expanded-byte/path/depth/work bounds before allocation/decompression; reject traversal, symlinks, macros, executable embeddings, external entities/relationships and remote resources. Match tracked changes/comments only through exact retained source/context evidence. Conflicting/ambiguous/unsupported changes remain explicit review items, not approximate attachments or applied edits. Preview/imported observations retain attribution to the existing **Word Revision** provenance category; that is not an extra workspace machine user or authenticated author. Applying reviewed changes uses normal graph/draft/Commit/receipt/recovery and current permissions. No original snapshot/history is rewritten.

## Platform, workloads and accessibility

Initial design acceptance profile is **macOS arm64 desktop with a release-pinned Chromium browser**; it matches the current native implementation target but is not a statement that general product acceptance passed. Windows/Linux/other architectures remain explicit future unaccepted profiles under D21A. Each release manifest records exact OS/browser/compiler/crypto/converter versions and profile hashes; “latest browser” is not a reproducible test identity. Mobile remains deferred. Existing macOS keychain/trust support does not establish accessibility or dissertation-scale capacity.

Use deterministic synthetic workload families for one owned source; repeated/nested/cyclic selection; many branches/history/receipts; two-human/two-provider concurrent private drafts; chat partial/cancellation; package/restore and academic export. Scale until the measured safe admission envelope is established on the selected profile. Record actual source bytes, unique/expanded occurrences, context/operation counts, time, peak memory, storage/WAL/temp growth and exact result/failure. The previously measured1,015,808-byte warm workflow is a bounded observation, not a promised capacity/latency target. No numeric safe limit or performance pass is fabricated: measured engineering limits and documented accepted workload review are required before advertising support. A profile refusing over-limit work explicitly is not a completeness proof or unlimited-scale guarantee.

Task-based desktop checks cover keyboard focus/navigation, selection/Undo, screen-reader labels/order/warnings, source under table/math widgets, both themes and relevant widths, graph/continuation and recovery/denial states. Require explicit cycle actions and no recursive no-click work. Record actual findings rather than assert WCAG certification from automated tests. Ambiguous/icon tooltips remain1500ms; self-labelled controls and large surfaces need no tooltip. Broad performance/accessibility/platform product qualification remains an execution/review gate, not a reason to guess missing numerical values in the specification.

## Governance, maintenance and acceptance

The owner remains approval authority; no new governance institution, automatic publication or licence scope is adopted. Preserve original/root/upstream licence texts, contributor/source lineage, private archives and exact hashes. Review contribution provenance and dependency licences before compilation; a conceptual influence, copied source and runtime library have distinct attribution. Publication needs a new explicit owner instruction; the earlier grants are exhausted. Maintain SemVer for application/API changes, separately versioned database/envelope/MCP/package/export profiles and exact compatibility matrices. Build identity pins source, lockfiles, toolchain, platform and explicit release build number. Node/Lean/database servers and separate installed Pandoc are not release-runtime requirements.

Required future checks exercise every target/profile/style and selected supplement, honest fallback/rights reports, no implicit citation refresh, private/denied data, hostile converter/DOCX input, exact spell corrections/Undo, missing/wrong resource hashes, interrupted jobs/temp cleanup and development/embedded parity. D20's continuous replication, owner-deferred Lean conversion and other platforms remain their explicitly staged future scopes. This design does not claim installation, measured numeric capacity, executed UI/export tests, native binary acceptance or a release.
