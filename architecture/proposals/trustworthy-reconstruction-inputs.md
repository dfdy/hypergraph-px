## Revision2 correction — accepted origin versus proposed representation

OWNER048 / RQ039 now supplies an accepted universal creation invariant in [M1](../Conceptual/identity-closure.c4), with [precise distinctions](../../docs/05-domain/core-object-model.md#creation-origin-and-placement--hpx-owner-048). Every node kind has known creation origin and a determinable parent or position; no originless-node exception is inferred. This proposal remains unadopted. Revision1's recommendations to refuse textual reconstruction for graph-only/no-notation inclusions and to reject partial notation are **withdrawn agent recommendations**, not owner decisions. They assumed inline markers too early. TEST156's dated static evidence remains unchanged and refers to revision1; its exact prior bytes/hash are preserved in the local checkpoint recorded by TEST157. No past proof or acceptance is rewritten.

Known structural placement does not settle source syntax or projection. OWNER047's retained original notation rule remains applicable where original notation is the source contribution; it does not by itself select a universal grammar or require every known placement to have inline syntax. The checked emission model still requires supplied source-faithful partitions; it proves no correspondence for an unrepresented placement. No conflict between the accepted origin invariant and OWNER047 has been established. If a future projection would replace existing original notation or invent boundary source, that concrete conflict must return to the owner before adoption.

## Change and rationale

Recommend specifying one **read-only, single-workspace, committed-source input contract** between existing application coordination, storage adapters and pure planning. Its job is to establish the real-input premises of the checked cycle/emission models before claiming trustworthy reconstruction. It introduces no endpoint, crate, identity, signature, schema, parser or notation syntax. Existing whole-owned editing, historical range reads and future composite editing retain their scope.

Canonical ownership stays with [M1 identity/closure](../Conceptual/identity-closure.c4), [Pure domain](../C3/pure-domain.c4), [Application coordination](../C3/remaining-c3.c4) and [Runtime/API](../C3/runtime-api.c4); precise input checks remain supporting contract/design material. No canonical view or layout needs changing to propose these mechanisms. This proposal neither transfers additional definitions nor closes a DOM001 migration gap.

## Proposed acquisition and validation boundary

The following are proposed validation stages, not a chosen wire/record format or executable pipeline. Each stage either supplies evidence for the next or returns a non-complete outcome. “Evidence” here means checked relationships to exact inputs, not a new signed attestation or trusted boolean provided by a caller.

1. **Admit one exact read intent.** The shared application API binds the acting workspace user, workspace, operation, root selection and source-only scope. Resolve any permitted live selection into explicit immutable versions under a consistent read view before reconstruction. The first proposed slice accepts already pinned committed selections, avoiding the unadopted timestamp/missing-value and marker mechanisms. It does not remove OWNER043/044's intended live capability. Check current authority before protected disclosure; unlock, a node selection or possession of a cached bundle is insufficient.
2. **Obtain authenticated full sources through storage.** Adapters open existing version/kind wrappers and authenticated envelope contexts, validate the claimed logical owner and exact immutable version plus relevant manifest/snapshot relationships, and return exact UTF8 source bytes. Wrong kinds/versions/owners/paths and inconsistent publication context fail. Do not reconstruct history from mutable draft text, a current head or a quote search. Same-node parent checks remain distinct from cross-identity derivation; no scanning all ancestry is required merely to prove a slice. Permission/consistent-view semantics for general compositions remain a design dependency, not solved by assuming a SQLite transaction or a decrypted record.
3. **Establish the selected slice.** For each source, validate `0 ≤ start ≤ end ≤ fullByteLength` and UTF8 scalar boundaries against those exact bytes; compute selected bytes directly as `full[start:end]`. Preserve CR/LF/CRLF and composed/decomposed forms. Retain the actual equality to that immutable full source, not merely a source length, quote or policy token. A selected-relative span `[lo,hi)` then maps to `[start+lo,start+hi)` with checked bounds/arithmetic. This is precisely the extra relation required by `absolute_copy_index`. Any browser UTF16 input must first be converted against the exact identified owned buffer; this contract does not reuse the browser's LF display projection as source.
4. **Establish ordered inclusion completeness.** Obtain authorial slot order, occurrence/role/exact selected target and known parent/position from the selected immutable structural context. Creation must already satisfy OWNER048; a reconstruction read cannot invent missing origin or repair history by guessing. Specify how the adopted representation relates every required structural inclusion to source contribution and output position. Where authored notation exists, establish its exact spans and recognition completeness; where it does not, do not equate absence of syntax with absence of placement or silently omit the inclusion. Check complete ordered correspondence without duplicate/extra/missing slots or contradictory positions. Ordinary references and collection membership are not automatically expansion slots. `PlanOK` checks a supplied literal/notation partition and tags for the current textual model; it does not prove general structural-to-text correspondence or cover alternative representations. Current one-occurrence manifests cannot supply that general relation.
5. **Close a finite selected environment.** Resolve every required target and every source-byte-affecting dependency to exact retained inputs within authorised scope. At stopped cycles retain the exact target descriptor/selection and ancestor context; stopping emission does not license an unverified target. Do not recursively enumerate infinite use paths or allocate a new selected state solely for each path. Apply OWNER045's finite table and structural recurrence semantics after input validation. Repeated uses may share payload bytes but retain their own full root-relative paths and context-dependent descendant selections. Missing dependencies or exhaustion cannot be reclassified as cycle boundaries. Pure planning receives supplied data and has no I/O/permission callback.
6. **Freeze interpretation with inputs.** Bind the exact source/cycle interpretation and any byte-affecting resources to this selected environment. A policy name, mutable configuration or parser version string alone does not establish the same interpretation function. It must either be demonstrably the same supported interpretation over those inputs or report unsupported. Literal/notation ownership is the including source; target and ancestor metadata remain separate. Historical reconstruction cannot silently use the newest parser, profile, provider metadata or selected heads. Physical retention/compatibility for interpretation resources needs its own design before persistence acceptance.
7. **Expose only a validated read result.** Run the bounded models' conceptual construction/emission over validated inputs; do not claim an extracted implementation bridge. Check actual operational work/byte/depth/output limits before or during costly acquisition and emission, including repeated uses; numeric budgets, charging rules and evaluator scheduling remain separately designed. Recheck current authority at the protected result boundary under the eventual revocation/consistency design. If authority or required context cannot be established, return no complete protected result. Warnings/navigation remain presentation metadata outside authored bytes. No draft save, Commit or new closed snapshot is produced by this read-only proposal.

## Missing, stale and unsupported inputs

Accepted obligations are explicit non-completeness, no unauthorised disclosure/substitution, exact history and separate cycle/failure outcomes. The diagnostic categories and first-slice restrictions below are **proposed**; they choose no error payload or permissions format.

| Condition | Proposed handling within the accepted obligations |
| --- | --- |
| Required immutable source, selection, byte-affecting resource or interpretation absent/inaccessible | No complete reconstruction. Distinguish missing/denied/unsupported internally where authorised; outward detail must not reveal protected existence. No bypass fetch or replacement by latest/cache/empty content. |
| Wrong source owner/version/kind, invalid wrapper, conflicting binding, malformed UTF8, bad range or partition | Reject the candidate with no success-labelled partial output; preserve immutable records for normal integrity/recovery handling. A valid cryptographic envelope does not excuse a contradictory semantic binding. |
| Head changes after an exact version was frozen | The pinned immutable read remains that exact version. A newer head does not make historical bytes stale. If an operation instead promised a particular current head/expected state, conflict/replan under that intent; do not retarget it silently. |
| Changed draft generation, source/map buffer or policy context | Discard/reject stale candidate evidence; obtain a fresh context through authorised operations. First slice excludes draft overlays; it does not change existing acknowledged-draft/Commit contracts. |
| Known structural placement without inline authored notation | Absence of notation does not imply absent origin, unplaced nodes or a permission to invent placement. The representation must specify the relation between structural placement, exact source and textual output before claiming complete correspondence. No product-level unsupported recommendation is adopted here. Do not omit a required inclusion or fabricate empty/generated notation to force it into the current model. |
| Requested range crosses a placement/source-projection boundary | Resolve against exact owned bytes and the adopted structural/projection semantics; unknown or ambiguous ownership cannot be guessed. No textual-marker clipping restriction is adopted. Existing exact historical byte/anchor reads retain their contract; future composite slicing must define contribution/position handling for the actual representation. Empty literal bytes do not establish missing inclusion evidence. |
| Resource exhaustion or unresolved finite closure discovery | Explicit incomplete/error, never a justified cycle boundary or “complete except for” closure. Authorised diagnostic previews must be explicitly incomplete and cannot be published/exported as exact complete reconstruction. |

## Real choices and recommendation

| Choice | Assessment |
| --- | --- |
| Validate authoritative structural positions against the exact source/projection interpretation | Recommended next design boundary. Where authored notation expresses inclusions, recognition completeness must agree with structural selections; where placement has no inline syntax, specify its source/output meaning explicitly. This does not choose syntax as universal placement authority or adopt a grammar. |
| Trust persisted/caller-supplied span annotations as sufficient | Bounds/tag checks are cheap, but do not establish that spans cover every actual inclusion. Such metadata may be an input/cache only when its exact source binding and completeness are independently established under an adopted interpretation. Encryption alone does not supply that proof. No new sidecar format is proposed. |
| Represent placement structurally with a separately defined text projection | A real representation option, not evidence of originless graph nodes. Requires complete ordered placement/source/output semantics consistent with OWNER047 wherever original notation exists. No physical representation or projection is selected here. |

Recommend **first review this evidence contract**, then specify the authoritative structural-position/source-projection relation for pinned committed compositions, including how original notation is preserved when present. Only after that relation is explicit can parser or loader correspondence be scoped. Do not infer a grammar from the synthetic Lean `<A>` fixtures or make inline markers the prerequisite for known placement. Existing whole-document reads remain bounded implementation evidence, not proof that general composite prerequisites are satisfied.

## Acceptance criteria and verification dependencies

These are proposed future gates, **not executed tests or newly proved requirements**:

- Each successful input preparation can trace full bytes, exact selected slice, immutable owner/version and every ordered slot to authorised authenticated sources; the row-to-source mapping preserves all byte-affecting context and does not erase distinct descendant selections. Alias mapping must be consistent, not a claim that abstract `Nat` IDs are already runtime identities.
- A concrete interpretation has soundness and completeness evidence for literal/notation recognition and slot alignment, including escaped/lookalike syntax where applicable, duplicate/missing/extra slots and representation-specific source ranges. Test mutations that preserve byte bounds/tag counts while changing actual syntax; structural validity alone must not pass as fidelity.
- Synthetic cases cover both repeated nested paths selecting different child versions and old snapshots after head changes, self/mutual cycles with exact stopped target/ancestor, known placements without inline notation, missing/ambiguous creation context, malformed/corrupt/wrong-kind inputs, denied access and revocation during acquisition/result disclosure, frozen-profile changes, resource exhaustion and dependency loss. No protected data appears through diagnostics or caches.
- Byte/slice cases cover empty text/literals, discontiguous selections as separately scoped inputs, CR/LF/CRLF, combining marks and supplementary scalars; UTF16 conversion rejects stale and split-surrogate coordinates. Scalar boundaries do not prove grapheme or semantic boundaries.
- A later model extension states and checks the adapter-input-to-`Bundle`/`Interpretation` relation; theorem premises remain explicit until discharged. Actual decoder/loader/parser/Rust correspondence and resource accounting require their own implementation evidence, not another example over trusted supplied rows. Changed formal assumptions require targeted replay at that later increment.
- Before any writes or real-data format acceptance, separately specify adapter DTO/kind/version and compatibility, atomic publication/recovery and older-reader refusal/upgrade behaviour. This read-only design does not waive those gates, current identity/permission gaps or client-held custody limits.
